# 🎮 Game Marketplace

**Game Marketplace** — backend-приложение игрового маркетплейса, разработанное на Java с использованием Spring Boot. Проект предназначен для размещения, покупки и продажи игровых товаров, оформления заказов и общения между покупателями и продавцами.

## 📌 Основные возможности

- Регистрация и авторизация пользователей.
- Авторизация с использованием JWT-токенов.
- Разделение пользователей по ролям: `USER` и `ADMIN`.
- Создание и просмотр игровых товаров.
- Размещение товаров от имени продавцов.
- Создание и обработка заказов.
- Оплата заказов с использованием внутреннего баланса.
- Перевод денежных средств продавцу после выполнения заказа.
- Отмена заказов и открытие споров.
- Административное управление заказами.
- Чат между покупателем и продавцом.
- Получение истории переписки.
- Получение списка диалогов с последними сообщениями.
- Хранение данных в базе данных H2.

## 🏗 Архитектура проекта

Проект построен на основе многослойной архитектуры.

```text
src/main/java/com/example/demo/
│
├── controller/     # REST-контроллеры
│
├── dto/             # Объекты передачи данных
│
├── entity/          # Сущности базы данных
│
├── repository/      # Работа с базой данных
│
├── service/         # Бизнес-логика приложения
│
└── security/        # JWT и Spring Security
```

### Назначение основных слоёв

- **Controller** — принимает HTTP-запросы и возвращает ответы клиенту.
- **DTO** — определяет структуру данных, передаваемых между клиентом и сервером.
- **Entity** — описывает сущности, которые хранятся в базе данных.
- **Repository** — выполняет операции получения, сохранения и изменения данных.
- **Service** — содержит бизнес-логику приложения.
- **Security** — отвечает за аутентификацию, авторизацию и проверку JWT-токенов.

Общий принцип обработки запроса:

`Postman → Controller → Service → Repository → Database`

## 👤 Роли пользователей

### USER
Обычный пользователь маркетплейса. Может выступать как покупателем, так и продавцом.

Возможности:
- Просмотр товаров.
- Размещение собственных товаров.
- Покупка товаров.
- Создание заказов.
- Общение с продавцами и покупателями.

### ADMIN
Администратор приложения.

Возможности:
- Выполнение административных операций.
- Управление заказами.
- Отмена заказов с учётом правил возврата средств.

## 📦 Работа с товарами

Товар содержит:
- ID;
- название;
- описание;
- цену;
- статус доступности;
- продавца;
- игру, к которой относится товар.

Продавец может размещать товары, просматривать свои объявления, обновлять их и делать недоступными.

## 🛒 Работа с заказами

Заказ связывает покупателя и приобретаемый товар.

Основные статусы заказа:

| Статус | Описание |
|---|---|
| `NEW` | Заказ создан, но ещё не оплачен |
| `PAID` | Заказ оплачен |
| `DELIVERED` | Продавец подтвердил выполнение заказа |
| `DISPUTE` | Покупатель открыл спор |
| `CANCELLED` | Заказ отменён |

Основной сценарий покупки:

1. Покупатель создаёт заказ.
2. Система проверяет доступность товара.
3. Покупатель оплачивает заказ.
4. Деньги списываются с баланса покупателя.
5. Продавец подтверждает выполнение заказа.
6. Деньги переводятся продавцу.

Также предусмотрена отмена заказов и обработка споров администратором.

## 💬 Чат между покупателем и продавцом

В проекте реализован REST-чат.

Возможности:
- Отправка сообщений покупателем.
- Ответы продавца.
- Получение истории переписки.
- Получение списка диалогов.
- Отображение последнего сообщения.
- Ограничение доступа к переписке её участниками.

Чат использует HTTP-запросы. WebSocket в текущей версии не используется.

## 🔐 Безопасность

Для защиты приложения используется Spring Security и JWT.

Основные особенности:
- Регистрация и вход пользователей.
- Генерация JWT-токена после авторизации.
- Передача токена через заголовок `Authorization: Bearer`.
- Защита закрытых API-маршрутов.
- Разграничение прав доступа по ролям.
- Ограничение административных маршрутов для пользователей с ролью `ADMIN`.

## 🚀 Запуск проекта

### Требования

Перед запуском необходимо установить:
- JDK 17 или выше;
- Git (если требуется клонирование репозитория).

### 1. Клонирование репозитория

```bash
git clone https://github.com/karatepacan228/game-marketplace.git
```

### 2. Переход в папку проекта

```bash
cd game-marketplace
```

### 3. Запуск приложения

В Windows PowerShell:

```powershell

```

```text

```

## 📡 Основные API-маршруты

### Авторизация

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/auth/register` | Регистрация |
| POST | `/api/auth/login` | Авторизация |

### Товары

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/items` | Создание товара |
| GET | `/api/items` | Получение всех товаров |
| GET | `/api/items/available` | Получение доступных товаров |
| GET | `/api/items/{id}` | Получение товара по ID |
| GET | `/api/items/seller/{sellerId}` | Товары продавца |
| PUT | `/api/items/{id}` | Обновление товара |
| DELETE | `/api/items/{id}?sellerId={sellerId}` | Скрытие товара |

### Чат

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/chat/items/{itemId}/messages` | Отправка сообщения |
| GET | `/api/chat/items/{itemId}/messages?buyerId={buyerId}` | История переписки |
| GET | `/api/chat/conversations` | Список диалогов |

### Администрирование

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/admin/orders/{orderId}/cancel` | Отмена заказа администратором |

Для остальных операций с заказами и балансом используйте маршруты, определённые в соответствующих контроллерах проекта.
